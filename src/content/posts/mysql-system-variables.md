port: MySQL 서버가 클라이언트 연결을 수신하는 포트입니다.
socket: MySQL 서버가 로컬 연결을 위해 수신 대기하는 Unix 소켓 파일 경로입니다.
user 및 password: MySQL 서버에 연결하는 데 사용되는 수출자 사용자의 사용자 이름과 암호입니다.
thread_cache_size: 스레드 캐시에있는 스레드 수입니다. 높은 값을 설정하면 짧은 기간 동안 많은 연결이있는 경우 성능을 향상시킬 수 있습니다.
thread_pool_size 및 thread_pool_max_threads: 이러한 설정은 MySQL 스레드 풀을 제어하며, 긴 기간 동안 많은 연결이있는 시스템에서 확장성과 성능을 향상시킬 수 있습니다.
max-connections: MySQL 서버에서 허용되는 최대 클라이언트 연결 수입니다.
wait_timeout 및 interactive_timeout: 클라이언트 연결이 유휴 상태인 경우 유지되는 시간 (초).
sort_buffer_size, read_buffer_size, join_buffer_size 및 read_rnd_buffer_size: 이러한 설정은 MySQL의 다양한 버퍼 및 캐시 영역의 크기를 제어하며 쿼리 성능에 영향을 미칠 수 있습니다.
max_allowed_packet: MySQL에서 단일 패킷 또는 생성 / 중간 문자열의 최대 크기입니다.
innodb_buffer_pool_size: InnoDB 테이블의 데이터 및 인덱스 페이지를 저장하는 InnoDB 버퍼 풀의 크기입니다. 시스템의 총 메모리의 50%에서 80% 사이의 값을 설정하는 것이 좋습니다.
innodb_write_io_threads 및 innodb_read_io_threads: 각각 쓰기 및 읽기 I / O 작업에 사용되는 스레드 수입니다. CPU 코어 수에 비례하는 값을 설정해야 합니다.
innodb_thread_concurrency: InnoDB 스토리지 엔진에서 최대 동시 스레드 수입니다.
innodb_flush_log_at_trx_commit: InnoDB 로그 버퍼가 디스크에 플러시되는 빈도입니다. 2의 값을 사용하면 좋은 내구성과 성

1. max_connections
- MySQL 서버가 동시에 처리할 수 있는 최대 클라이언트 연결 수를 결정하는 변수입니다.
- 기본값은 151이며, 이 값 이상으로 클라이언트가 연결을 시도하면 "Too many connections" 오류가 발생합니다.
- 서버에서 처리할 수 있는 동시 클라이언트 수에 따라 이 값을 적절하게 조정해야 합니다.
1. tmp_table_size
- 임시 테이블이 메모리에 생성될 때 사용되는 버퍼 크기를 결정하는 변수입니다.
- 큰 값으로 설정하면 임시 테이블의 처리 속도가 빨라질 수 있지만, 메모리 부족으로 인해 서버가 중단될 수 있습니다.
- 이 값은 모든 클라이언트가 공유하는 글로벌 변수이므로, 각각의 세션에서 임시 테이블을 사용하는 쿼리가 많은 경우 이 값을 적절하게 조정해야 합니다.
1. innodb_buffer_pool_size
- InnoDB 스토리지 엔진에서 사용되는 버퍼 풀의 크기를 결정하는 변수입니다.
- InnoDB 스토리지 엔진은 데이터와 인덱스를 메모리에 캐시하여 디스크에서 읽는 빈도를 줄이는데, 이 때 사용되는 버퍼 풀의 크기를 이 변수로 조정할 수 있습니다.
- 버퍼 풀의 크기를 적절하게 설정하면 디스크에서 데이터를 읽어오는 횟수를 줄여서 성능을 향상시킬 수 있습니다.
1. query_cache_type
- 쿼리 캐시의 사용 여부를 결정하는 변수입니다.
- 값으로는 0, 1, 2가 있으며, 0은 캐시를 사용하지 않음을 의미하고, 1은 캐시를 사용하도록 설정하는 것입니다.
- 2는 캐시를 사용하지만, 이전의 결과를 갱신하지 않는 것입니다.
- 캐시를 사용하도록 설정하면 동일한 쿼리가 반복 수행될 때 캐시된 결과를 사용하므로 성능이 향상될 수 있습니다.
1. sort_buffer_size

1. innodb_log_buffer_size: InnoDB의 로그 버퍼 크기를 조정하는 변수입니다. 이 변수를 높게 설정하면 InnoDB가 커밋된 데이터를 디스크에 기록하기 전에 버퍼에 보관하는 양이 증가하므로 디스크 기록에 대한 지연을 줄일 수 있습니다.
2. innodb_flush_log_at_trx_commit: InnoDB의 트랜잭션 로그 기록 방식을 제어하는 변수입니다. 기본값은 1이며, 이 경우 매 트랜잭션 커밋 시 로그를 디스크에 강제로 기록합니다. 이 값을 0으로 설정하면 커밋 시 로그를 메모리에만 기록하므로 성능이 향상됩니다. 그러나 장애 발생 시 데이터의 일관성이 보장되지 않습니다.
3. max_allowed_packet: MySQL에서 한 번에 전송할 수 있는 최대 패킷 크기를 제어하는 변수입니다. 이 값을 높이면 더 큰 데이터를 전송할 수 있지만, 이에 따른 메모리 사용량도 증가하므로 적절한 값을 선택해야 합니다.
4. query_cache_size: 쿼리 캐시의 크기를 제어하는 변수입니다. 이 값을 높이면 자주 사용되는 쿼리 결과를 캐시하여 다음에 동일한 쿼리가 실행될 때 성능이 향상됩니다. 그러나 큰 값을 설정하면 캐시된 데이터를 유지하는 데 필요한 메모리 사용량이 증가하므로 주의해야 합니다.
5. thread_cache_size: 쓰레드 캐시의 크기를 제어하는 변수입니다. 이 값을 높이면 MySQL 서버의 부하가 증가했을 때 더 많은 쓰레드를 생성하는 대신 기존 쓰레드를 재사용할 수 있으므로 성능이 향상됩니다. 그러나 큰 값을 설정하면 캐시된 쓰레드를 유지하는 데 필요한 메모리 사용량이 증가하므로 주의해야 합니다.
6. tmp_table_size: 임시 테이블의 메모리 크기를 제어하는 변수입니다. 이 값을 높이면 정렬이나 그룹화 등의 작업에서 임시 테이블을 사용하는 빈도가 줄어들어 성능이 향상됩니다. 그러나 임시 테이블이 매우 큰 경우 디스크에 저장되므로, 적절한 값을 선택해야 합니다.

1. innodb_log_buffer_size: InnoDB 트랜잭션 로그를 저장하는 버퍼 크기를 설정하는 세션 변수입니다. 이 값은 InnoDB가 변경 내용을 로그에 기록할 때 사용됩니다. 기본값은 16MB이며, 큰 트랜잭션 또는 많은 트랜잭션을 처리하는 경우 증가시켜야 할 수 있습니다.
2. innodb_flush_log_at_trx_commit: InnoDB가 트랜잭션 로그를 언제 디스크에 기록하는지를 제어하는 세션 변수입니다. 값이 0인 경우 InnoDB는 트랜잭션 로그를 커밋할 때마다 디스크에 즉시 기록하지 않으므로 성능이 향상됩니다. 그러나 시스템 장애가 발생한 경우 데이터 손실 가능성이 있습니다. 값이 1인 경우, 트랜잭션 로그는 커밋할 때마다 디스크에 즉시 기록됩니다. 이는 가장 안정적인 방법이지만 성능이 저하될 수 있습니다. 값이 2인 경우 InnoDB는 로그 버퍼에만 기록하고 1초마다 디스크에 기록합니다. 이 방법은 일반적으로 가장 균형 잡힌 성능/안정성 옵션입니다.
3. innodb_file_per_table: 이 세션 변수가 활성화되면 InnoDB는 모든 테이블에 대해 별도의 데이터 파일을 사용합니다. 이렇게 하면 더 큰 유연성과 성능 향상이 가능합니다. 기본적으로 이 옵션은 활성화되어 있으며, 대부분의 경우 그대로 두는 것이 좋습니다.
4. innodb_stats_on_metadata: 이 세션 변수가 활성화되면 InnoDB는 메타데이터 조회 시 자동으로 테이블 통계를 업데이트합니다. 이렇게 하면 실행 계획이 개선되어 쿼리 성능이 향상될 수 있습니다. 그러나 테이블이 큰 경우에는 시간이 오래 걸릴 수 있으므로 이러한 업데이트를 수동으로 수행하는 것이 더 나을 수도 있습니다.

1. `join_buffer_size`: `JOIN` 연산에서 사용되는 버퍼 크기를 설정하는 세션 변수입니다. `JOIN` 작업을 할 때 MySQL 서버는 두 개 이상의 테이블을 조인하고, 그 결과를 생성하는 데 사용됩니다. 이때 `join_buffer_size`는 빠른 `JOIN` 처리를 위해 버퍼링을 사용합니다.
2. `thread_cache_size`: MySQL 서버는 각 클라이언트의 요청을 처리할 때마다 스레드를 생성합니다. `thread_cache_size`는 이러한 스레드를 캐싱할 수 있는 크기를 설정하는 세션 변수입니다. 이를 통해 새로운 스레드를 생성하지 않고 기존의 스레드를 재사용할 수 있어서 성능 향상을 기대할 수 있습니다.
3. `innodb_buffer_pool_size`: InnoDB 스토리지 엔진에서 사용되는 버퍼 풀의 크기를 설정하는 세션 변수입니다. InnoDB는 테이블 데이터와 인덱스를 메모리에 저장하기 위해 버퍼 풀을 사용합니다. 이 버퍼 풀의 크기는 적절히 설정해야 전반적인 성능을 향상시킬 수 있습니다.
4. `innodb_log_buffer_size`: InnoDB 스토리지 엔진에서 사용되는 로그 버퍼의 크기를 설정하는 세션 변수입니다. InnoDB는 로그 버퍼를 사용하여 트랜잭션 로그를 버퍼링합니다. 이를 통해 디스크 I/O를 줄이고 높은 성능을 유지할 수 있습니다.
5. `innodb_sort_buffer_size`: InnoDB 스토리지 엔진에서 사용되는 정렬 버퍼의 크기를 설정하는 세션 변수입니다. InnoDB는 `ORDER BY`나 `GROUP BY`와 같은 연산을 수행할 때 정렬을 수행합니다. 이때 `innodb_sort_buffer_size`를 적절히 설정하면 정렬 작업을 더 빠르게 처리할 수 있습니다.
