DynamoDB는 "먼저 액세스 패턴부터"라는 말이 유명하다. 그 설계를 눈으로 하면서 검증할 수 있는 게 AWS 공식 무료 GUI, **NoSQL Workbench**다.

## 무엇인가

DynamoDB(및 Keyspaces)용 데스크톱 앱. 무료로 배포되고, DynamoDB Local이나 실제 계정에 붙여 쓸 수 있다.

- **데이터 모델러** — 테이블·인덱스·속성 설계
- **비주얼라이저** — 파티션 키/정렬 키로 데이터가 어떻게 묶이는지 시각화
- **오퍼레이션 빌더** — Query/Scan을 GUI로 만들고 코드(파이썬·JS 등)로 내보내기

## 액세스 패턴 → 모델

DynamoDB 모델링은 RDB처럼 정규화가 아니라 **액세스 패턴을 먼저 나열**하고 그걸 만족하는 키 설계를 거꾸로 찾는다.

- 파티션 키(PK)·정렬 키(SK) 설계
- **facet** — 같은 테이블을 애플리케이션 관점(엔티티)별로 나눠 보는 뷰
- **GSI(글로벌 보조 인덱스)** 로 추가 액세스 패턴 커버

> [!tip]
> 단일 테이블 설계(single-table design)를 검토할 때 특히 유용하다. 여러 엔티티를 한 테이블에 담고 facet으로 각 엔티티 관점을 확인하면, 키 충돌·중복을 미리 잡는다.

## 실무 흐름

1. **데이터 모델러**에서 테이블·GSI·facet 설계
2. 샘플 데이터 몇 건 입력 → **비주얼라이저**로 파티션에 어떻게 들어가는지 확인
3. **오퍼레이션 빌더**로 실제 Query를 짜보고, 원하는 결과가 한 번에 나오는지 검증
4. 코드로 내보내 애플리케이션에 반영
5. DynamoDB Local이나 개발 계정에 커밋해서 실제 동작 확인

## 정리

- DynamoDB 설계는 **액세스 패턴 우선** — NoSQL Workbench로 그걸 시각적으로 검증
- 모델러·비주얼라이저·오퍼레이션 빌더 3종으로 설계→검증→코드화
- 단일 테이블 설계 검토에 특히 강하다

"일단 만들고 나중에 인덱스 추가"가 어려운 DynamoDB에선, 설계 단계에서 눈으로 확인하는 이 도구가 실수를 크게 줄여준다.
