MySQL 엔진은 인덱스 스캔을 수행하기 위해 다음과 같은 과정을 거칩니다.

1. 인덱스 스캔 타입 결정
  - MySQL 엔진은 쿼리의 WHERE 절과 JOIN 절 등을 분석하여 적절한 인덱스 스캔 타입을 결정합니다.
  - 인덱스 스캔 타입에는 Unique Scan, Range Scan, Full Scan 등이 있습니다.
  - 적절한 인덱스 스캔 타입을 선택하면, MySQL 엔진은 해당 스캔 타입에 맞는 인덱스 스캔 방법을 결정합니다.
1. 인덱스 스캔 방법 결정
  - 인덱스 스캔 방법에는 Index Scan, Index Range Scan, Index Full Scan 등이 있습니다.
  - 인덱스 스캔 방법은 스토리지 엔진에 따라 다르며, InnoDB 스토리지 엔진에서는 B-Tree를 사용하여 인덱스 스캔을 수행합니다.
  - MySQL 엔진은 B-Tree를 탐색하여 필요한 데이터 페이지의 위치를 찾습니다.
1. 데이터 페이지 로딩
  - MySQL 엔진은 스토리지 엔진에게 데이터 페이지를 요청하고, 데이터 페이지를 메모리에 로딩합니다.
  - InnoDB 스토리지 엔진에서는 페이지 크기가 16KB이며, 인덱스 데이터 페이지에는 여러 개의 레코드가 포함될 수 있습니다.
1. 레코드 필터링
  - MySQL 엔진은 로딩한 데이터 페이지에서 WHERE 절과 JOIN 절 등의 조건을 확인하여 필요한 레코드를 찾습니다.
  - 필요한 레코드를 찾을 때는 다양한 알고리즘을 사용합니다. 예를 들어, Unique Scan에서는 레코드를 하나만 찾으면 되므로, B-Tree를 이용한 이진 탐색 알고리즘을 사용합니다.
1. 결과 반환
  - MySQL 엔진은 필요한 레코드를 찾은 후, SELECT 절에 명시된 컬럼을 읽어와서 결과를 반환합니다.
  - 결과는 임시 테이블에 저장되거나, 클라이언트에 직접 전송될 수 있습니다.
이와 같은 과정을 거쳐 MySQL 엔진은 인덱스 스캔을 수행합니다. 이때 MySQL 엔진과 스토리지 엔진 간의 상호작용이 발생하며, 이를 최적화하여 쿼리 실행 속도를 향상시키는 것이 MySQL 엔진의 역할입니다.
